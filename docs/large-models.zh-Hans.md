# 大模型加载

[English](large-models.md) · **简体中文**

## 分阶段预览

面向约 2 GB 的 GLB / glTF，先给出可操作的概览，再在后台增加细节：

1. **结构概览（边界框）**：只读取 JSON 中的包围盒及节点变换，不读取几何 BIN。界面明确标注这是结构框，并非实际表面。
2. **几何预览**：后台生成较低面数和较小纹理的模型，准备好后替换概览。
3. **细节预览（已简化）**：从原文件再次生成更细的一档。当前画面在准备期间仍可旋转和缩放，替换保留实时相机和复位视角。

可以点击「停止细化」。切换或关闭模型会取消旧准备任务；细化失败保留已经显示的模型。停止或失败后重新打开同一文件可重试。下次打开直接复用已验证的最高档缓存；修改原文件或外部资源会使缓存失效。

分阶段预览不会改变原文件。GLB / glTF 导出仍使用原始资源；透明 PNG 使用当前可见档位。高分辨率抠图期间暂停细节交换。

## 何时启用

满足任一条件即进入分阶段处理，包括已经压缩的 meshopt 模型：

- 文件及外部资源总量或 buffer 声明总量 ≥ 200 MiB；
- 场景实例合计超过 200 万三角面；
- 估算解码几何或纹理超过 128 MiB；
- 场景绘制次数超过 512，或实例数超过 10,000。

预览阶段在发布缓存前检查实际输出：

| 档位 | 三角面上限 | 几何预算 | 纹理预算 | 单图最大边长 | 绘制次数上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 几何预览 | 30 万 | 64 MiB | 64 MiB | 512 px | 1,024 |
| 细节预览 | 200 万 | 256 MiB | 256 MiB | 1,024 px | 4,096 |

纹理数量较多时会进一步降低单图尺寸。预算按解码后的保守开销计算，含 mipmap，而不是只看压缩文件大小；预览贴图使用内存内 WebP 编码，避免沙盒临时文件问题；应用同时附带 KTX2/Basis 解码器，支持离线加载。未知纹理尺寸不会按零开销处理。输出超过预算时停止提升档位，不强行将原始 2 GB 模型塞入窗口。

## 当前边界

- 这是分阶段**简化预览**，不是无损空间分块或视点流式 LOD，也不承诺最终加载全部原始面数和纹理。
- gltfpack 转换仍需读取整个输入。转换内存不等于渲染预算，首次细化耗时取决于几何、贴图、硬件及磁盘。转换一次只运行一个任务。
- JSON 中缺少可靠 bounds，或含 GPU instancing 时，直接等待首档几何，不显示错误的结构框。结构最多显示 2,048 个框，额外框合并为整体范围。
- 必需的 Draco 压缩暂不能由现有转换器生成预算内预览；保留可用概览并报告细化失败。小型 Draco 模型沿用原有加载方式。
- 本轮大模型管线覆盖 GLB / glTF。大型 OBJ / STL 会明确提示先转换为 GLB / glTF；小型 OBJ / STL 保持可用。
- 内嵌 base64 的大型 `.gltf` 元数据扫描只保留有限前缀，但仍须顺序扫描输入；首概览速度不等同于具有独立 JSON chunk 的 GLB。
- 无损空间分块、任意 2 GB 资产的完整质量显示仍需独立的流式渲染架构。

## 实测记录

2026-09-30，Apple Silicon、32 GiB 内存：生成了实际分配 2.005 GiB、22,429,696 个非退化三角面的 GLB，包含 32 个网格/材质和 4 张贴图。所有几何数据均有实际引用，不是稀疏文件或空白填充。

- 结构准备：约 3 ms（不含应用启动及首帧渲染）。
- 几何预览：约 9.99 s，284,960 面；转换进程树最大 RSS 约 4.45 GiB。
- 细节预览：约 9.05 s，1,899,968 面；转换进程树最大 RSS 约 5.41 GiB。
- 热缓存直接返回细节档，准备时间 < 1 ms。
- 500 ms 发出取消，约 557 ms 返回取消结果，临时缓存已清理。

这是可复现的合成几何负载，不代表所有 2 GB CAD、扫描或动画资产都具有相同表现。浏览器与原生测试记录见 [tests/README.md](../tests/README.md)。
